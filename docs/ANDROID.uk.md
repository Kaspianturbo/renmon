# Renmon для Android

Статус: тестовий APK 0.1.3 зібрано для Android 8.0+ (arm64-v8a). Підпис і вміст перевірено. Запуск на реальному телефоні, UI, системні дозволи, CSV-пікер і фізичний Bluetooth ELM ще потребують перевірки; локальні тести її не замінюють.

## Архітектура

`renmon/android_app.py` збирає мобільну оболонку PyWebView та той самий Monitor, який використовує desktop. HTML/CSS/JS завантажуються з APK через локальний документ, без HTTP-сервера. Політика читання ECU, каталог X91, декодування, групування DID та журнал SQLite спільні.

`features/android/bluetooth.py` реалізує Transport через Android BluetoothSocket (Classic SPP/RFCOMM). Перелік містить уже спарені пристрої. BLE-only адаптери не підтримуються. Дозвіл BLUETOOTH_CONNECT запитується при відкритті переліку на Android 12+, геолокація та сканування не використовуються. Спарювання і ввімкнення Bluetooth виконуються в системних налаштуваннях.

`features/android/bridge.py` додає метадані платформи й запит дозволу до обмеженого DesktopAPI. Прямих ELM-команд у JS немає. `Connection` отримує фабрику транспорту через конструктор; desktop продовжує використовувати SerialTransport.

`features/android/lifecycle.py` зупиняє читання й автопідключення при паузі Activity, включно з блокуванням екрана та переходом у системний вибір файлу. Поточний socket закривається; після повернення потрібне явне «Почати». Під час паузи UI-watchdog не завершує застосунок; при зависанні активного UI watchdog залишається ввімкненим.

`features/android/export.py` використовує ACTION_CREATE_DOCUMENT. CSV записується через ContentResolver у вибране користувачем місце. Доступ до всього сховища не запитується. SQLite та діагностичні журнали зберігаються у приватній директорії застосунку.

## Складання на macOS Apple Silicon

```sh
cd renmon
source .venv-android/bin/activate
export JAVA_HOME="/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
python packaging/prepare_android.py
cd packaging/android
buildozer -v android debug
cd ../..
python packaging/sign_android.py dist/android/renmon-0.1.3-arm64-v8a-debug.apk
```

Шлях до репозиторію в команді вище слід замінити на свій. `prepare_android.py` створює окремий staging лише з кодом, UI та профілями: без журналів, venv, macOS helper і ключів. PyWebView 6.2.1 і p4a commit зафіксовані у buildozer.spec. JAR bridge береться з тієї ж версії PyWebView у build-середовищі. APK: `dist/android/`.

Перший запуск завантажує SDK/NDK та запитує ліцензію Google. Автоматичне прийняття вимкнене. Debug-збірка використовує технічний debug-сертифікат, не персональні дані автора. Перед Gradle-пакуванням `packaging/android/privacy.py` замінює абсолютний префікс домашньої директорії комп’ютера збирання на нейтральний `/build…` у байткоді та native-бібліотеках, зберігаючи довжини й бінарні зміщення; архіви перепаковуються з коректними контрольними сумами. Перед передаванням APK додатково перевіряються сертифікат і вміст пакета. Фінальний тестовий APK повторно підписується постійним локальним ключем із сертифікатом `CN=Renmon`. Ключ і пароль зберігаються в `~/.config/renmon/android-signing` із правами 700/600, поза staging і репозиторієм. Їх потрібно зберегти для наступних оновлень; до APK вони не потрапляють. Фінальний файл: `dist/android/Renmon-0.1.3-android-arm64.apk`.

## Перевірка на телефоні

1. Встановити APK, відкрити деморежим, перевірити плитки, графік, fullscreen і CSV.
2. Спарити V-Link у системному Bluetooth (PIN адаптера — за його документацією).
3. Вибрати режим автомобіля; відкрити список адаптерів, надати дозвіл, відкрити список повторно й вибрати V-Link.
4. Визначити профіль і запустити читання. Без підключеного автомобіля очікується помилка/таймаут, а не штучні дані.
5. Згорнути застосунок: читання та autoconnect мають зупинитися. Повернення не повинно автоматично відновлювати опитування.
6. Перевірити відмову в дозволі, вимкнений Bluetooth, обрив з’єднання й повторний запуск.

Фоновий моніторинг, BLE, USB і магазин Google Play не входять до першої версії.
